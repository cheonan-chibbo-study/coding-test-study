          이해하신 대로 이 코드는 `S`, `A`, `B` 세 곳에서 각각 다익스트라를 돌린 후, 마지막에 모든 노드를 돌면서 합산의 최솟값을 찾고 있습니다.

          이 방식이 왜 정답이 되는지, 그리고 서은님이 처음에 생각하신 훌륭한 접근법이 어떻게 이 코드로 연결되는지 차근차근 풀어드릴게요!

          ### 1. 서은님의 원래 아이디어와 이 코드의 연결 고리

          서은님이 생각하신 풀이 과정을 다시 정방향(출발지 기준)으로 정리하면 다음과 같습니다.

          > **"출발점 `S`에서 어떤 지점 `X`까지 같이 택시를 타고 간 다음(동승), 그 지점 `X`에서 헤어져서 한 명은 `A`로, 한 명은 `B`로 따로 간다."**
          >

          이걸 수식(거리)으로 표현하면 어떻게 될까요?

            - `S`에서 `X`까지의 최단 거리: **`S ➡️ X`**
            - `X`에서 `A`까지의 최단 거리: **`X ➡️ A`**
            - `X`에서 `B`까지의 최단 거리: **`X ➡️ B`**

          즉, 우리가 구해야 하는 총비용은 `(S ➡️ X) + (X ➡️ A) + (X ➡️ B)`가 됩니다.

          여기서 가장 중요한 핵심은 "둘이 도대체 어느 지점(`X`)에서 헤어지는 게 가장 이득일까?"입니다.

          경우에 따라서는 아예 처음(출발지 `S`)부터 따로 가는 게 이득일 수도 있고, `A`네 집까지 같이 갔다가 `B`만 더 이동하는 게 이득일 수도 있습니다. 즉, **모든 노드가 환승 지점(`X`)의 후보**가 될 수 있는 것이죠.

          ### 2. 왜 S, A, B 세 곳에서만 다익스트라를 돌릴까?

          그렇다면 모든 후보 지점 `X`(1번 노드부터 $N$번 노드까지)에 대해 전부 다익스트라를 돌려야 할까요? 그건 양이 너무 많아 시간 초과가 날 것입니다.

          여기서 그래프의 양방향성(무방향 그래프)이라는 특성을 이용한 역발상이 들어갑니다.

            - `S ➡️ X`의 최단 거리는?

              👉 `S`에서 출발하는 다익스트라 한 번으로 **모든 `X`에 대한 거리**를 알 수 있습니다. (`costs[0]`)

            - `X ➡️ A`의 최단 거리는?

              👉 도로가 양방향이므로, `X`에서 `A`로 가는 거리나 **`A`에서 `X`로 가는 거리**나 똑같습니다! 따라서 `A`에서 출발하는 다익스트라 한 번이면 **모든 `X`에 대한 거리**를 알 수 있습니다. (`costs[1]`)

            - `X ➡️ B`의 최단 거리는?

              👉 마찬가지로 **`B`에서 `X`로 가는 거리**와 같습니다. `B`에서 출발하는 다익스트라로 해결됩니다. (`costs[2]`)


            결과적으로 **`S`, `A`, `B` 세 지점에서만 다익스트라를 딱 한 번씩(총 3번)** 돌려놓으면, 지도상에 존재하는 그 어떤 지점 `X`를 환승지로 고르더라도 `(S ➡️ X) + (X ➡️ A) + (X ➡️ B)` 값을 $O(1)$만에 바로 계산할 수 있게 되는 것입니다.
            
            ### 3. 마지막 루프의 의미: "가장 싼 환승지 찾기"
            
            이제 준비물이 다 갖춰졌으니, 마지막 루프를 돌며 비교만 하면 됩니다.
            
            Python
            
            # 
            
            ```
            for i in range(1, n + 1):
                answer = min(answer, costs[0][i] + costs[1][i] + costs[2][i])
            ```
            
            만약 `i = 5`일 때 이 값이 최소라면? "5번 노드까지 같이 택시를 타고 가다가, 5번 노드에서 찢어져서 각자 집으로 가는 게 제일 싸다!"는 뜻이 됩니다.
            
            - 만약 같이 안 타는 게 제일 싸다면 어떻게 될까요? 자연스럽게 `i = s`(출발지)일 때 `costs[0][s]`가 0이 되면서, `(S ➡️ S) + (S ➡️ A) + (S ➡️ B)` 즉, 처음부터 따로 가는 비용이 최솟값으로 선택됩니다.
            - 만약 `A`네 집까지 같이 가는 게 제일 싸다면? `i = a`일 때 `costs[1][a]`가 0이 되면서 자동으로 그 비용이 선택됩니다.
            
            ### 💡 요약하자면
            
            이 코드는 다른 기발한 알고리즘을 쓴 게 아니라, **서은님이 생각하신 "어디선가 만나서(헤어져서) 각자 간다"라는 로직을 완벽하게 구현한 코드**입니다.
            
            다만 성능을 위해 "헤어지는 지점 `X`를 기준으로 각각 다익스트라를 돌리는 것"이 아니라, 양방향 노드의 성질을 활용해 "목적지인 `S`, `A`, `B`를 기준 삼아 거꾸로 다익스트라를 3번만 돌려놓고 최적의 `X`를 찾아내는 방식"을 선택한 것이죠!

- Java로 2차 풀이를 진행하여 `11분 42초`만에 문제를 해결했다.

## 🧑‍🔬 문제 분석

무방향 가중치 그래프 정보, A, B의 집 위치, 시작 노드 정보가 주어질 때 A와 B가 합승 + 각자 집으로 향하는 모든 경우의 수 중 가장 택시비가 적게 나올 수 있는 경우를 찾아 그 택시비를 반환하는 문제이다.

- 자세한 조건은 문제를 참고하자.

문제에 주어진 제약 조건은 다음과 같다.

### **[제한사항]**

- 지점갯수 n은 3 이상 200 이하인 자연수입니다.
- 지점 s, a, b는 1 이상 n 이하인 자연수이며, 각기 서로 다른 값입니다.
    - 즉, 출발지점, `A`의 도착지점, `B`의 도착지점은 서로 겹치지 않습니다.
- fares는 2차원 정수 배열입니다.
- fares 배열의 크기는 2 이상 `n x (n-1) / 2` 이하입니다.
    - 예를들어, n = 6이라면 fares 배열의 크기는 2 이상 15 이하입니다. (`6 x 5 / 2 = 15`)
    - fares 배열의 각 행은 [c, d, f] 형태입니다.
    - c지점과 d지점 사이의 예상 택시요금이 `f`원이라는 뜻입니다.
    - 지점 c, d는 1 이상 n 이하인 자연수이며, 각기 서로 다른 값입니다.
    - 요금 f는 1 이상 100,000 이하인 자연수입니다.
    - fares 배열에 두 지점 간 예상 택시요금은 1개만 주어집니다. 즉, [c, d, f]가 있다면 [d, c, f]는 주어지지 않습니다.
- 출발지점 s에서 도착지점 a와 b로 가는 경로가 존재하는 경우만 입력으로 주어집니다.

추가로 이 문제는 정확도와 효율성을 따로 체크하는 문제이므로 시간 복잡도가 제법 빡빡하다.

## 🤔 풀이 고민

혼자서 풀이를 떠올리지 못해 결국 풀이를 찾아봤다. 찾아본 풀이가 굉장히 신박해서 인상 깊다.

문제에서 제시하는 목표는 `s` 지점에서 두 승객이 택시를 탑승하여 각자의 목적지까지 갈 수 있는 최저 택시 요금을 구하는 것이다. 이 때 두 승객은 특정 지점까지 택시를 합승하여 비용을 절약할 수 있다.

이 때 `x` 지점까지 택시를 합승한다 하면 두 사람의 귀가 경로는 `s→x→a, s→x→b`가 되며 택시 비용은 `cost(s→x) + cost(x→a) + cost(x→b)`가 된다.

또한 해당 그래프는 무방향 그래프이기에 `cost(x→a) == cost(a→x), cost(x→b) == cost(b→x)`가 된다.

즉 `s, a, b` 3개의 지점에서 `x` 지점까지 도달하는 최소 비용의 합을 `x` 지점을 조정해가며 구하면 된다.

여기서 3개의 지점에서 `x` 지점까지 도달하는 최소 비용들은 다음과 같이 구할 수 있다.

우선 첫번째 방법은 3개의 지점에서 각각 다익스트라를 수행하는 것이다. 다익스트라는 시작 노드에서 각 노드까지 도달하는 최소 비용들을 반환하며 그렇기에 각 3개의 노드에서 다익스트라를 수행하면 임의의 노드 `x` 까지 도달하는 최소 비용을 알 수 있다.

- 두번째 방법, 플로이드 위셜 알고리즘

  두번째 방법은 플로이드 워셜 알고리즘을 수행하는 것이다. 플로이드 워셜 알고리즘은 모든 노드에서 각기 다른 노드에 도달하는 최소 비용을 반환하는 알고리즘이다. 이를 통해 각 3개의 노드에서 임의의 노드 `x` 까지 도달하는 최소 비용을 알 수 있다.

  하지만 기업 코테에서 이 알고리즘을 사용할일이 진짜 거의 없으니 그냥 첫 번째 방법을 사용하면 좋을거 같다.


즉 문제 상황으로 돌아오면, 3개의 지점에서 각 지점까지 도달하는 최소 비용을 저장하고 모든 지점을 순회하며 `cost(s→x) + cost(x→a) + cost(x→b)`의 최소값을 찾으면 문제에서 요구하는 최저 택시 요금이 나오게 된다.

- GPT 추가 설명

  좋아.

  지금 헷갈리는 포인트는 이거야 👇

  > “왜
  >
  >
  > `cost(s→x) + cost(a→x) + cost(b→x)`
  >
  > 의 최소값이 전체 최적해가 되는가?”
  >

  이걸 **직관 + 논리** 두 단계로 설명해줄게.
    
  ---

  # 1️⃣ 먼저 구조를 정확히 보자

  합승이라는 건 반드시 이런 구조야:

    ```
    s ────────┐
              ↓
            (어떤 지점 x)
              ↙        ↘
             a          b
    ```

  즉,

    - s에서 출발
    - 어느 순간 x에서 갈라짐
    - 이후는 각자 최단경로로 이동

  👉 이 “갈라지는 지점”이 반드시 존재해.
    
  ---

  # 2️⃣ 어떤 최적 경로가 있다고 가정해보자

  최적의 합승 경로가 이렇게 생겼다고 치자:

    ```
    s → p1 → p2 → p3 → ... → pK
    ```

  여기까지는 같이 타고 가다가

  어떤 지점 `pK = x`에서 갈라졌다고 하자.

  그 이후:

    ```
    x → ... → a
    x → ... → b
    ```
    
  ---

  # 3️⃣ 이제 중요한 질문

  ## ❓ s → x 구간은 최단 경로일까?

  👉 **무조건 최단 경로여야 한다.**

  왜?

  만약 s→x가 최단이 아니라면

  더 짧은 경로로 바꿀 수 있음 → 전체 비용 더 줄어듦 → 모순
    
  ---

  ## ❓ x → a 구간도 최단 경로일까?

  👉 역시 무조건 최단 경로여야 한다.

  왜냐면 그 이후는 이미 각자 따로 가니까

  최단이 아니면 더 줄일 수 있음 → 모순
    
  ---

  ## ❓ x → b도?

  👉 당연히 동일
    
  ---

  # 🔥 결론

  어떤 최적해든 반드시 이런 형태야:

    ```
    (최단 s→x)
    +
    (최단 x→a)
    +
    (최단 x→b)
    ```
    
  ---

  # 4️⃣ 그래서 우리가 하는 것

  우리는 모든 x를 다 시도해본다:

    ```
    cost(s→x)
    + cost(x→a)
    + cost(x→b)
    ```

  그 중 최소값을 고른다.
    
  ---

  # 5️⃣ 그런데 왜 a→x를 써도 되냐?

  그래프는 **무방향**이야.

    ```
    cost(a→x) == cost(x→a)
    cost(b→x) == cost(x→b)
    ```

  그래서 a에서 다익스트라 한 거야.
    
  ---

  # 6️⃣ 직관적 비유

  이걸 지도에 대입해보자.

  서울에서 출발해서

    - 한 명은 인천
    - 한 명은 수원

  으로 가야 한다고 생각해.

  어떤 최적 전략이 있을까?

    1. 서울에서 같이 가다가
    2. “어딘가”에서 갈라지고
    3. 각자 최단 경로로 간다

  그 “어딘가”가 x야.
    
  ---

  # 7️⃣ 반례가 있을 수 있을까?

  혹시 이런 경우를 생각할 수 있어:

  > “x 이후에 다시 합쳐졌다가 또 갈라지면?”
  >

  그건 절대 최적이 될 수 없어.

  왜냐면:

    - 합쳐졌다가 다시 갈라지는 건
    - 결국 중복 이동이 발생함
    - 더 짧게 줄일 수 있음

  그래서 최적 구조는 항상:

    ```
    하나의 분기점 x
    ```

  구조로 단순화된다.
    
  ---

  # 8️⃣ 그래서 공식이 성립하는 이유

  우리는:

    - s→x의 최단 거리
    - a→x의 최단 거리
    - b→x의 최단 거리

  를 모두 알고 있다.

  그리고 최적해는 반드시 어떤 x에서 갈라진 구조이므로

  👉 모든 x를 검사하면 최적해가 반드시 포함된다.
    
  ---

  # 9️⃣ 한 줄로 수학적으로 말하면

  최적해의 분기점을 x*라고 하자.

  그러면 최적 비용은:

    ```
    cost(s→x*)
    + cost(x*→a)
    + cost(x*→b)
    ```

  이고

  우리는 모든 x를 검사하므로

  x*도 반드시 검사된다.

  따라서 최솟값이 정답이 된다.

  짧고 핵심만 정리해줄게 👇
    
  ---

  ## 1️⃣ 다익스트라 3번 수행

    - 정점 수: **V ≤ 200**
    - 간선 수: **E ≤ n(n-1)/2 ≈ 20,000**

  다익스트라 1번 시간복잡도:

    ```
    O(E log V)
    ```

  힙을 사용했으므로 `log V`가 붙는다.
    
  ---

  ## 2️⃣ 전체 시간복잡도

  다익스트라를 3번 수행하므로:

    ```
    O(3E log V)
    ≈ O(E log V)
    ```

  최대값을 대입해보면:

    ```
    ≈ 20,000 × log(200)
    ≈ 20,000 × 8
    ≈ 160,000
    ```

  👉 연산량이 약 16만 수준이라 매우 작다.
    
  ---

  ## 3️⃣ 마지막 반복문

    ```
    for i in range(n):
    ```

  → O(n) = 최대 200

  이 부분은 전체 복잡도에 거의 영향을 주지 않는다.
    
  ---

  # 🎯 최종 시간복잡도

    ```
    O(E log V)
    ```
    
  ---

  ✔ 핵심 한 줄 요약

  > 노드 수가 200으로 작고, 다익스트라를 3번만 수행하기 때문에
  >
  >
  > 전체 연산량이 10만 단위 수준이라 시간 제한 내에 충분히 해결 가능하다.

## 🏃 코드 작성 과정

### 구현하지 못한 부분 구현

위에 기술한 풀이를 코드로 구현하면 다음과 같다. 이 코드는 최종 정답 처리를 받는다.

```python
from collections import defaultdict
from heapq import heappush, heappop

def solution(n, s, a, b, fares):
    # 메인 로직
    graph = defaultdict(list)
    for c, d, f in fares:
        graph[c].append((f, d))
        graph[d].append((f, c))
    
    answer = float('inf')
    
    #✅ s, a, b 3개의 노드에서 모든 노드까지 도달하는 최소 비용을 저장한다.
    costs = [[float('inf') for _ in range(n + 1)] for _ in range(3)]
    
    #✅ s, a, b 3개의 노드에서 각각 다익스트라 알고리즘을 수행한다.
    for i, start_v in enumerate([s, a, b]):
        pq = []
        heappush(pq, (0, start_v))
        costs[i][start_v] = 0
        
        while pq:
            cur_cost, cur_v = heappop(pq)
            
            for cost, next_v in graph[cur_v]:
                next_cost = cur_cost + cost
                
                if costs[i][next_v] > next_cost:
                    costs[i][next_v] = next_cost
                    heappush(pq, (next_cost, next_v))

    #✅ 모든 노드를 순회하며 cost(s->x) + cost(x->a) + cost(x->b)의 최소비용을 반환한다.
    for i in range(1, n + 1):
        answer = min(answer, costs[0][i] + costs[1][i] + costs[2][i])
    
    return answer
```

### Java 풀이

- solution01

    ```java
    import java.util.*;
    
    class Solution {
        public int solution(int n, int s, int a, int b, int[][] fares) {
            Map<Integer, List<int[]>> graph = new HashMap<>();
            for (int[] fare : fares) {
                graph.computeIfAbsent(fare[0], key -> new ArrayList<>()).add(new int[]{fare[1], fare[2]});
                graph.computeIfAbsent(fare[1], key -> new ArrayList<>()).add(new int[]{fare[0], fare[2]});
            }
            
            int[][] visited = new int[3][n + 1];
            for (int i = 0; i < 3; i++) {
                for (int j = 1; j < n + 1; j++) {
                    visited[i][j] = Integer.MAX_VALUE;
                }
            }
            
            // 메인 로직
            int[] startVertex = {s, a, b};
            for (int i = 0; i < 3; i++) {
                PriorityQueue<Node> pq = new PriorityQueue<>((v1, v2) -> {
                    return Integer.compare(v1.totalCost, v2.totalCost);
                });
                pq.offer(new Node(startVertex[i], 0));
                visited[i][startVertex[i]] = 0;
                
                while (!pq.isEmpty()) {
                    Node cur = pq.poll();
                    
                    if (cur.totalCost > visited[i][cur.vertex]) {
                        continue;
                    }
                    
                    for (int[] next : graph.computeIfAbsent(cur.vertex, key -> new ArrayList<>())) {
                        int nextTotalCost = cur.totalCost + next[1];
                        
                        if (nextTotalCost < visited[i][next[0]]) {
                            pq.offer(new Node(next[0], nextTotalCost));
                            visited[i][next[0]] = nextTotalCost;
                        }
                    }
                }
            }
            
            int answer = Integer.MAX_VALUE;
            for (int i = 1; i < n + 1; i++) {
                answer = Math.min(answer, visited[0][i] + visited[1][i] + visited[2][i]);
            }
                
            return answer;
        }
        
        class Node {
            int vertex;
            int totalCost;
            
            public Node(int vertex, int totalCost) {
                this.vertex = vertex;
                this.totalCost = totalCost;
            }
        }
    }
    ```
