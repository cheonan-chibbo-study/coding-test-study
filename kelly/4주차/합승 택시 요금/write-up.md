## 👀 제한 시간 안에 어디까지 해냈는가?

제한 시간 `30분`안에 문제를 해결하지 못했다. 몇가지 아이디어를 떠올리기는 했지만 시간 복잡도 상으로 시간 초과가 발생할거라 판단했고, 추가 시간을 사용해도 풀이를 떠올리지 못할거 같아서 결국 풀이를 찾아봤다.

- 찾아본 풀이가 굉장히 신박해서 머리를 한 대 얻어맞은 기분이었다… 이런걸 대체 어떻게 떠올리는건지 신기하다…

---

## 🧑‍🔬 문제 분석

무방향 가중치 그래프 정보, A, B의 집 위치, 시작 노드 정보가 주어질 때 A와 B가 합승 + 각자 집으로 향하는 모든 경우의 수 중 가장 택시비가 적게 나올 수 있는 경우를 찾아 그 택시비를 반환하는 문제이다.

- 자세한 조건은 문제를 참고하자.

문제에 주어진 제약 조건은 다음과 같다.

### **[제한사항]**

- 지점갯수 n은 3 이상 200 이하인 자연수입니다.
- 지점 s, a, b는 1 이상 n 이하인 자연수이며, 각기 서로 다른 값입니다.
    - 즉, 출발지점, `A`의 도착지점, `B`의 도착지점은 서로 겹치지 않습니다.
- fares는 2차원 정수 배열입니다.
- fares 배열의 크기는 2 이상 `n x (n-1) / 2` 이하입니다.
    - 예를들어, n = 6이라면 fares 배열의 크기는 2 이상 15 이하입니다. (`6 x 5 / 2 = 15`)
    - fares 배열의 각 행은 [c, d, f] 형태입니다.
    - c지점과 d지점 사이의 예상 택시요금이 `f`원이라는 뜻입니다.
    - 지점 c, d는 1 이상 n 이하인 자연수이며, 각기 서로 다른 값입니다.
    - 요금 f는 1 이상 100,000 이하인 자연수입니다.
    - fares 배열에 두 지점 간 예상 택시요금은 1개만 주어집니다. 즉, [c, d, f]가 있다면 [d, c, f]는 주어지지 않습니다.
- 출발지점 s에서 도착지점 a와 b로 가는 경로가 존재하는 경우만 입력으로 주어집니다.

추가로 이 문제는 정확도와 효율성을 따로 체크하는 문제이므로 시간 복잡도가 제법 빡빡하다.

## 🤔 풀이 고민

혼자서 풀이를 떠올리지 못해 결국 풀이를 찾아봤다. 찾아본 풀이가 굉장히 신박해서 인상 깊다.

문제에서 제시하는 목표는 `s` 지점에서 두 승객이 택시를 탑승하여 각자의 목적지까지 갈 수 있는 최저 택시 요금을 구하는 것이다. 이 때 두 승객은 특정 지점까지 택시를 합승하여 비용을 절약할 수 있다.

이 때 `x` 지점까지 택시를 합승한다 하면 두 사람의 귀가 경로는 `s→x→a, s→x→b`가 되며 택시 비용은 `cost(s→x) + cost(x→a) + cost(x→b)`가 된다.

또한 해당 그래프는 무방향 그래프이기에 `cost(x→a) == cost(a→x), cost(x→b) == cost(b→x)`가 된다.

즉 `s, a, b` 3개의 지점에서 `x` 지점까지 도달하는 최소 비용의 합을 `x` 지점을 조정해가며 구하면 된다.

여기서 3개의 지점에서 `x` 지점까지 도달하는 최소 비용들은 다음과 같이 구할 수 있다.

우선 첫번째 방법은 3개의 지점에서 각각 다익스트라를 수행하는 것이다. 다익스트라는 시작 노드에서 각 노드까지 도달하는 최소 비용들을 반환하며 그렇기에 각 3개의 노드에서 다익스트라를 수행하면 임의의 노드 `x` 까지 도달하는 최소 비용을 알 수 있다.

- 두번째 방법, 플로이드 위셜 알고리즘

  두번째 방법은 플로이드 워셜 알고리즘을 수행하는 것이다. 플로이드 워셜 알고리즘은 모든 노드에서 각기 다른 노드에 도달하는 최소 비용을 반환하는 알고리즘이다. 이를 통해 각 3개의 노드에서 임의의 노드 `x` 까지 도달하는 최소 비용을 알 수 있다.

  하지만 기업 코테에서 이 알고리즘을 사용할일이 진짜 거의 없으니 그냥 첫 번째 방법을 사용하면 좋을거 같다.


즉 문제 상황으로 돌아오면, 3개의 지점에서 각 지점까지 도달하는 최소 비용을 저장하고 모든 지점을 순회하며 `cost(s→x) + cost(x→a) + cost(x→b)`의 최소값을 찾으면 문제에서 요구하는 최저 택시 요금이 나오게 된다.

- GPT 추가 설명

  좋아.

  지금 헷갈리는 포인트는 이거야 👇

  > “왜
  >
  >
  > `cost(s→x) + cost(a→x) + cost(b→x)`
  >
  > 의 최소값이 전체 최적해가 되는가?”
  >

  이걸 **직관 + 논리** 두 단계로 설명해줄게.
    
  ---

  # 1️⃣ 먼저 구조를 정확히 보자

  합승이라는 건 반드시 이런 구조야:

    ```
    s ────────┐
              ↓
            (어떤 지점 x)
              ↙        ↘
             a          b
    ```

  즉,

    - s에서 출발
    - 어느 순간 x에서 갈라짐
    - 이후는 각자 최단경로로 이동

  👉 이 “갈라지는 지점”이 반드시 존재해.
    
  ---

  # 2️⃣ 어떤 최적 경로가 있다고 가정해보자

  최적의 합승 경로가 이렇게 생겼다고 치자:

    ```
    s → p1 → p2 → p3 → ... → pK
    ```

  여기까지는 같이 타고 가다가

  어떤 지점 `pK = x`에서 갈라졌다고 하자.

  그 이후:

    ```
    x → ... → a
    x → ... → b
    ```
    
  ---

  # 3️⃣ 이제 중요한 질문

  ## ❓ s → x 구간은 최단 경로일까?

  👉 **무조건 최단 경로여야 한다.**

  왜?

  만약 s→x가 최단이 아니라면

  더 짧은 경로로 바꿀 수 있음 → 전체 비용 더 줄어듦 → 모순
    
  ---

  ## ❓ x → a 구간도 최단 경로일까?

  👉 역시 무조건 최단 경로여야 한다.

  왜냐면 그 이후는 이미 각자 따로 가니까

  최단이 아니면 더 줄일 수 있음 → 모순
    
  ---

  ## ❓ x → b도?

  👉 당연히 동일
    
  ---

  # 🔥 결론

  어떤 최적해든 반드시 이런 형태야:

    ```
    (최단 s→x)
    +
    (최단 x→a)
    +
    (최단 x→b)
    ```
    
  ---

  # 4️⃣ 그래서 우리가 하는 것

  우리는 모든 x를 다 시도해본다:

    ```
    cost(s→x)
    + cost(x→a)
    + cost(x→b)
    ```

  그 중 최소값을 고른다.
    
  ---

  # 5️⃣ 그런데 왜 a→x를 써도 되냐?

  그래프는 **무방향**이야.

    ```
    cost(a→x) == cost(x→a)
    cost(b→x) == cost(x→b)
    ```

  그래서 a에서 다익스트라 한 거야.
    
  ---

  # 6️⃣ 직관적 비유

  이걸 지도에 대입해보자.

  서울에서 출발해서

    - 한 명은 인천
    - 한 명은 수원

  으로 가야 한다고 생각해.

  어떤 최적 전략이 있을까?

    1. 서울에서 같이 가다가
    2. “어딘가”에서 갈라지고
    3. 각자 최단 경로로 간다

  그 “어딘가”가 x야.
    
  ---

  # 7️⃣ 반례가 있을 수 있을까?

  혹시 이런 경우를 생각할 수 있어:

  > “x 이후에 다시 합쳐졌다가 또 갈라지면?”
  >

  그건 절대 최적이 될 수 없어.

  왜냐면:

    - 합쳐졌다가 다시 갈라지는 건
    - 결국 중복 이동이 발생함
    - 더 짧게 줄일 수 있음

  그래서 최적 구조는 항상:

    ```
    하나의 분기점 x
    ```

  구조로 단순화된다.
    
  ---

  # 8️⃣ 그래서 공식이 성립하는 이유

  우리는:

    - s→x의 최단 거리
    - a→x의 최단 거리
    - b→x의 최단 거리

  를 모두 알고 있다.

  그리고 최적해는 반드시 어떤 x에서 갈라진 구조이므로

  👉 모든 x를 검사하면 최적해가 반드시 포함된다.
    
  ---

  # 9️⃣ 한 줄로 수학적으로 말하면

  최적해의 분기점을 x*라고 하자.

  그러면 최적 비용은:

    ```
    cost(s→x*)
    + cost(x*→a)
    + cost(x*→b)
    ```

  이고

  우리는 모든 x를 검사하므로

  x*도 반드시 검사된다.

  따라서 최솟값이 정답이 된다.
    
  ---

  # 🎯 핵심 깨달음

  이 문제는 사실:

  > "합승 경로 문제"가 아니라
  >
  >
  > "공통 경로(prefix)를 갖는 두 최단 경로 문제"
  >

  야.
    
  ---

  # 💬 진짜 핵심 한 문장

  > 어떤 최적 합승 경로든
  >
  >
  > 반드시 어떤 지점 x까지는 함께 최단 경로로 이동하고
  >
  > 그 이후는 각자 최단 경로로 이동한다.
  >
  > 그래서 모든 x를 검사하면 정답이 된다.
>

이 방식은 시간 복잡도 상으로도 효율적이기 때문에 문제를 해결할 수 있다.

- GPT 시간 복잡도 계산

  짧고 핵심만 정리해줄게 👇
    
  ---

  ## 1️⃣ 다익스트라 3번 수행

    - 정점 수: **V ≤ 200**
    - 간선 수: **E ≤ n(n-1)/2 ≈ 20,000**

  다익스트라 1번 시간복잡도:

    ```
    O(E log V)
    ```

  힙을 사용했으므로 `log V`가 붙는다.
    
  ---

  ## 2️⃣ 전체 시간복잡도

  다익스트라를 3번 수행하므로:

    ```
    O(3E log V)
    ≈ O(E log V)
    ```

  최대값을 대입해보면:

    ```
    ≈ 20,000 × log(200)
    ≈ 20,000 × 8
    ≈ 160,000
    ```

  👉 연산량이 약 16만 수준이라 매우 작다.
    
  ---

  ## 3️⃣ 마지막 반복문

    ```
    for i in range(n):
    ```

  → O(n) = 최대 200

  이 부분은 전체 복잡도에 거의 영향을 주지 않는다.
    
  ---

  # 🎯 최종 시간복잡도

    ```
    O(E log V)
    ```
    
  ---

  ✔ 핵심 한 줄 요약

  > 노드 수가 200으로 작고, 다익스트라를 3번만 수행하기 때문에
  >
  >
  > 전체 연산량이 10만 단위 수준이라 시간 제한 내에 충분히 해결 가능하다.
>

## 🏃 코드 작성 과정

### 구현하지 못한 부분 구현

위에 기술한 풀이를 코드로 구현하면 다음과 같다. 이 코드는 최종 정답 처리를 받는다.

```python
from collections import defaultdict
from heapq import heappush, heappop

def solution(n, s, a, b, fares):
    # 메인 로직
    graph = defaultdict(list)
    for c, d, f in fares:
        graph[c].append((f, d))
        graph[d].append((f, c))
    
    answer = float('inf')
    
    #✅ s, a, b 3개의 노드에서 모든 노드까지 도달하는 최소 비용을 저장한다.
    costs = [[float('inf') for _ in range(n + 1)] for _ in range(3)]
    
    #✅ s, a, b 3개의 노드에서 각각 다익스트라 알고리즘을 수행한다.
    for i, start_v in enumerate([s, a, b]):
        pq = []
        heappush(pq, (0, start_v))
        costs[i][start_v] = 0
        
        while pq:
            cur_cost, cur_v = heappop(pq)
            
            for cost, next_v in graph[cur_v]:
                next_cost = cur_cost + cost
                
                if costs[i][next_v] > next_cost:
                    costs[i][next_v] = next_cost
                    heappush(pq, (next_cost, next_v))

    #✅ 모든 노드를 순회하며 cost(s->x) + cost(x->a) + cost(x->b)의 최소비용을 반환한다.
    for i in range(1, n + 1):
        answer = min(answer, costs[0][i] + costs[1][i] + costs[2][i])
    
    return answer
```
