# 30분내 어디까지 풀었는가
풀지못함
# 왜 못풀었는가 - 
### 풀이가 안떠올랐는지 / 어떻게 풀지는 알겠는데 구현을 못하겠다.
시간초과

# 접근방법

1. 광고를 삽입할 수 있는 모든 시작 시간을 하나씩 확인하면 최대 36만 초(99시간 59분 59초)이고, 각 구간마다 시청 시간을 다시 계산하면 시간 초과가 발생한다.

2. 따라서 모든 시청 로그를 초 단위로 변환한 뒤, `start += 1`, `end -= 1` 방식의 차분 배열(Difference Array)을 사용했다.

3. 각 로그에 대해:
    - 시청 시작 시간에는 +1
    - 시청 종료 시간에는 -1

   을 기록하면 해당 구간의 시청자 수를 효율적으로 표현할 수 있다.

4. 1차 누적합을 수행하여 각 초마다 몇 명이 시청 중인지 구한다.

   예시:

   ```text
   차분 배열
   1 0 0 1 0 -1 0 0 0 0 -1

   1차 누적합
   1 1 1 2 2 1 1 1 1 1 0
   ```

5. 2차 누적합을 수행하여 0초부터 해당 시점까지의 누적 시청 시간을 구한다.

   ```text
   시청자 수
   1 1 1 2 2 1 1 1 1 1 0

   2차 누적합
   1 2 3 5 7 8 9 10 11 12 12
   ```

   이렇게 하면 특정 구간의 총 시청 시간을 O(1)에 구할 수 있다.

6. 광고 시작 시간을 0초부터 끝까지 이동시키면서 구간합을 계산한다.

   ```java
   구간 시청 시간 = prefix[end] - prefix[start - 1]
   ```

7. 가장 큰 누적 시청 시간을 가지는 시작 시간을 저장하고, 마지막에 다시 `HH:MM:SS` 형식으로 변환하여 반환한다.

# 시간/공간 복잡도

시간 복잡도:

```text
O(P + L)
```

- P : 재생 시간(초)
- L : 로그 개수

세부적으로는

```text
로그 순회      : O(L)
1차 누적합     : O(P)
2차 누적합     : O(P)
광고 구간 탐색 : O(P)
```

따라서

```text
O(L + P)
```

이다.

---

공간 복잡도:

```text
O(P)
```

타임라인 배열 하나를 사용하므로 재생 시간 크기만큼의 공간이 필요하다.

# 배운점

### 1. 차분 배열(Difference Array)

구간 전체를 순회하며 값을 증가시키는 것이 아니라

```java
arr[start] += 1;
arr[end] -= 1;
```

만 기록한 뒤 누적합을 수행하면 각 위치의 값을 복원할 수 있다는 것을 배웠다.

---

### 2. 누적합을 두 번 사용할 수 있다

보통 누적합은 한 번만 사용한다고 생각했는데,

- 1차 누적합 → 각 초의 시청자 수
- 2차 누적합 → 누적 시청 시간

처럼 누적합 결과에 다시 누적합을 적용할 수 있다는 것을 배웠다.

---

### 3. 구간합을 O(1)에 구할 수 있다

2차 누적합 이후에는

```java
prefix[end] - prefix[start - 1]
```

만으로 광고 구간의 총 시청 시간을 구할 수 있다.

덕분에 모든 광고 시작 위치를 탐색해도 시간 초과가 발생하지 않는다.

---

### 4. 2차 누적합에서 값이 겹쳐 보여도 문제없다

예를 들어 시청자 수가

```text
1 1 1 2 2 1
```

이라면

```text
1 2 3 5 7 8
```

이 된다.

겉보기에는 이전 값이 계속 더해져서 중복 계산처럼 보이지만,

실제로는 "0초부터 현재 시점까지의 총 시청 시간"을 저장하는 것이므로 의도된 동작이다.

이 덕분에 나중에 두 값의 차를 이용해 원하는 구간의 총 시청 시간을 빠르게 계산할 수 있다.
