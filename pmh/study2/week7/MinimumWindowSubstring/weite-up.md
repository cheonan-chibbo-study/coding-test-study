# 문제링크
https://leetcode.com/problems/minimum-window-substring/
# 30분내 어디까지 풀었는가
30분내 풀기 완려 그러나 힌트를 보고 풀었다
# 왜 못풀었는가 - 
### 풀이가 안떠올랐는지 / 어떻게 풀지는 알겠는데 구현을 못하겠다.


# 접근방법

1. `t`에 필요한 문자의 개수를 `need` 배열에 저장한다.
2. `right` 포인터를 한 칸씩 이동하며 현재 문자를 윈도우에 포함시킨다.
3. 현재 문자가 아직 필요한 문자라면(`need[add] > 0`) `remain`을 감소시킨다.
4. 문자를 사용했음을 표시하기 위해 `need[add]--`를 수행한다.
    - `need`가 음수가 되면 해당 문자가 필요한 개수보다 더 많이 포함되어 있다는 의미이다.
5. `remain == 0`이 되면 현재 윈도우가 `t`의 모든 문자를 포함하므로,
   `left`를 이동시키며 가능한 한 윈도우를 줄인다.
6. 윈도우를 줄이는 과정에서 더 짧은 길이를 발견하면 `minLen`과 `minStart`를 갱신한다.
7. 왼쪽 문자를 제거할 때 `need[remove]++`를 수행하고, 그 결과 `need[remove] > 0`이 되면
   다시 필요한 문자가 부족해진 것이므로 `remain++`를 하여 윈도우 축소를 종료한다.
8. 모든 탐색이 끝난 후 저장된 `minStart`, `minLen`을 이용해 가장 짧은 부분 문자열을 반환한다.

# 시간/공간 복잡도

시간 복잡도: **O(n + m)**
- `n` = `s.length()`
- `m` = `t.length()`
- `left`, `right` 포인터가 각각 최대 `n`번씩만 이동하므로 전체는 선형 시간이다.

공간 복잡도: **O(1)**
- 크기가 128인 배열만 사용하므로 입력 크기와 관계없이 일정한 공간을 사용한다.

# 배운점

- 슬라이딩 윈도우에서는 현재 구간의 상태를 배열 하나로 관리하면 효율적으로 문제를 해결할 수 있다.
- `need[c]`는 단순히 필요한 개수가 아니라 **현재 윈도우 기준으로 아직 부족한 개수**를 의미한다.
- `need[c]`가 음수라는 것은 해당 문자가 필요한 개수보다 더 많이 포함되어 있다는 뜻이며, 이를 통해 중복 문자를 별도의 자료구조 없이 처리할 수 있다.
- `remain`을 이용하면 매번 윈도우 전체를 검사하지 않아도 현재 윈도우가 조건을 만족하는지 O(1)에 판단할 수 있다.
- 슬라이딩 윈도우에서는 조건을 만족하면 바로 `left`를 이동시켜 윈도우를 최소화하는 패턴이 자주 사용된다.
