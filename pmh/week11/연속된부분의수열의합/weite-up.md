# 문제링크

# 30분내 어디까지 풀었는가
30분내 풀었지만 시간 초과됨
# 왜 못풀었는가 - 
### 풀이가 안떠올랐는지 / 어떻게 풀지는 알겠는데 구현을 못하겠다.


# 접근방법
```java
class Solution {
    public int[] solution(int[] sequence, int k) {
        int n = sequence.length;
        int bestL = 0;
        int bestR = n - 1;
        int minLen = Integer.MAX_VALUE;

        for (int i = 0; i < n; i++) {
            int sum = 0;
            for (int j = i; j < n; j++) {
                sum += sequence[j];
                if (sum == k) {
                    int len = j - i;
                    if (len < minLen) {
                        minLen = len;
                        bestL = i;
                        bestR = j;
                    }
                    break;
                }
                if (sum > k) break;
            }
        }

        return new int[]{bestL, bestR};
    }
}
```
기존 풀이는 단순 반복문을 통해 구간합을 구하는 거였다   
그러나 sequence 의 최대 길이는 1,000,000 이고 2개의 반복문은 O(n^2) 이므로 최대 1,000,000 ^2 의 연산이 이루어 질수있으므로 시간초과 가 난다.  
그래서 단순 반목문이 아닌 투포인터 방식을 사용해 풀어여한다  
- left~right 를 현재 구간으로 잡고 생각한다
- 합이 k보다 커지면 left 를 줄여서 합을 줄인다
- 합 k 가 되면 정답 후보
- 그중 길이가 가장 짧은 구간을 저장한다
- 투포인터는 포문안에 while 있어 얼핏보면 O(n^2) 같아 보이지만 아니다
- 왜 O(n) 인가?
  - right 포인터 
    - right는 0부터 n-1까지 한 번만 증가함 → 총 n번
  - left 포인터 
    - left도 뒤로만 움직임 
    - 절대 다시 왼쪽으로 가지 않음 
    - 즉 left도 최대 n번만 이동함
  - while(sum > k)가 여러 번 도는 것처럼 보여도,
    전체 실행 동안 left++가 일어나는 총 횟수는 최대 n번이다.
- 전체 포인터 이동 횟수는
  - ```java
    right 이동 n번 + left 이동 n번
    ```

# 배운점
## 투 포인터를 언제 쓰냐
1. 연속된 구간을 다룰 때

예:
- 부분합
- 연속된 부분 수열
- 특정 조건을 만족하는 최소 길이 구간
- 문자열에서 조건 만족하는 부분 문자열

대표 예시:
- 합이 k 이상인 최소 길이 부분배열
- 합이 k인 연속 부분수열
- 문자열에서 모든 문자를 포함하는 최소 윈도우
- 이럴 때는 보통 슬라이딩 윈도우 형태의 투 포인터를 많이 씀.

2. 정렬된 배열에서 두 수의 합 같은 문제

예:

- 정렬된 배열에서 합이 x인 두 수 찾기
- 두 수의 차가 특정 값인 경우 찾기
- 세 수의 합 문제에서 내부적으로 두 포인터 사용

대표 패턴:

- 합이 작으면 왼쪽 증가
- 합이 크면 오른쪽 감소
3. “모든 구간을 다 보면 O(n^2)인데, 포인터를 한 번씩만 움직이면 될 것 같을 때  
브루트포스로는 시작점 하나 잡고 끝점을 매번 다시 다 확인해서 O(n^2)이 된다,  
문제 성질상 포인터가 뒤로만 이동해도 충분하면
투 포인터로 O(n) 또는 O(n log n)까지 줄일 수 있다.

## 투 포인터를 쓰기 좋은 조건
1. 연속 구간 문제

배열의 연속된 부분 구간을 다룰 때

예:
[left ~ right] 구간의 합, 길이, 조건 만족 여부

2. 정렬되어 있거나, 정렬하면 의미가 있을 때

정렬된 상태에서  
왼쪽은 작은 값
오른쪽은 큰 값  
으로 두고 조건을 비교하면서 움직일 수 있음.

3. 값의 변화 방향이 예측 가능할 때

예를 들어 자연수 배열에서 구간합은  
오른쪽 늘리면 합 증가
왼쪽 줄이면 합 감소  
이렇게 단조성이 있음.  
이런 문제는 투 포인터가 잘 먹힘.
