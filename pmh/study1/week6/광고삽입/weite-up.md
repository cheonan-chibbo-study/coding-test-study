# 문제링크

# 30분내 어디까지 풀었는가
00~총신청시간 까지 했을때 광고시간을 1초씩 시작해가면서 시청자가 가장많은 구간을 선택해야겠다고 생각함
하지만 구현이 생각이 아난서 시간초과
# 접근방법
1) 시간을 초로 바꾼다

예를 들어 "01:30:15" 같은 문자열 상태로는 계산이 너무 불편함.

그래서 전부 초로 바꾸면:

01:30:15 → 5415초

이렇게 되어 배열 인덱스로 바로 사용할 수 있다.

2) 왜 start += 1, end -= 1 을 하는이유

예를 들어 어떤 사람이 10초 ~ 15초 동안 시청했다고 한다면.

그러면:

10초부터 시청자 수 1명 증가

15초부터는 더 이상 안 봄

그래서 배열에:

timeline[10] += 1;
timeline[15] -= 1;

이렇게만 기록하고,
나중에 누적합을 하면 각 초마다 실제 시청자 수가 복원된다.

이걸 차분 배열 느낌으로 생각한다.

3) 첫 번째 누적합 의미

예를 들어 차분 배열이 이렇게 생겼다고 한다면.

index:    0 1 2 3 4 5
value:    0 1 0 0 -1 0

누적합 하면:

index:    0 1 2 3 4 5
viewer:   0 1 1 1 0 0

즉, 각 초마다 몇 명이 보고 있는지 알 수 있다.

4) 두 번째 누적합 의미

첫 번째 누적합 후 배열이:

0초: 1명
1초: 2명
2초: 3명
3초: 2명

이라면,

두 번째 누적합을 하면:

0초까지 총 시청 시간 = 1
1초까지 총 시청 시간 = 1 + 2 = 3
2초까지 총 시청 시간 = 1 + 2 + 3 = 6
3초까지 총 시청 시간 = 1 + 2 + 3 + 2 = 8

이제 어떤 구간의 총 시청 시간도 빠르게 구할 수 있다.

예를 들어 [a ~ b] 구간합은:

prefix[b] - prefix[a - 1]

5) Long 을 쓴는이유

재생 시간은 최대 100시간이고,
각 초마다 시청자 수가 많이 겹칠 수 있어서
누적합이 int 범위를 넘어갈 수 있다.

그래서 long[] 을 써야 안전하다.

예시 감각

광고 길이가 3초라고 하고, 각 초마다 시청자 수가:

초:        0 1 2 3 4 5
시청자수:   1 2 3 2 1 0

광고 시작 시각별 총 시청 시간은:

0초 시작 → 1+2+3 = 6

1초 시작 → 2+3+2 = 7

2초 시작 → 3+2+1 = 6

3초 시작 → 2+1+0 = 3

그래서 정답은 1초.


시간 복잡도

로그 처리: O(logs.length)

누적합 2번: O(playSeconds)

광고 시작점 탐색: O(playSeconds)

즉 전체는 대략:

O(logs.length + playSeconds)

재생 시간이 최대 100시간 = 360000초 정도라서 충분히 가능하다.
