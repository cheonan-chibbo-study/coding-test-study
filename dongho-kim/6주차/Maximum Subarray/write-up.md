# 접근 방법
## 1. 시작
처음에는 아래 다섯 가지 접근 방법에 대해 떠올렸다.  
아마 시험이라면 2번 방법을 적용해서 해결했을 것 같다.  
그런데 문제에서 가능하면 O(N) 만에 시도해보라고 했고, 문제 유형이 DP인 만큼 4번과 5번 방법을 시도해보았다.

```plaintext
1. 2중 for문으로 부분 수열 범위를 잡고, for문으로 해당 범위 탐색하면서 합을 구한다. O(n^3)
2. 누적합?
   arr = [-2,1,-3,4,-1,2,1,-5,4]
   prefix_sum = [-2, -1, -4, 0, -1, 1, 2, -3, 1]
누적합구하고, 2중 for문으로 범위의 합을 구한다. O(n^2)
3. nums의 범위 중에서 숫자 2개 뽑아서, 해당 범위만큼의 sum을 구한다.
   nC2 = n! / 2!(n-2)! = (10^4)! / 2!(10^4 - 2)!
4. 각 숫자를 뽑거나 뽑지 않는 모든 경우를 따졌을 때, 부분 수열의 합을 구한다. O(2^N)
5. 4번에서 메모이제이션
```

## 2. 실패
하지만 접근 방법 자체가 틀렸다.  

## 3. AI에게 헬프
결국 AI에게 도움을 받아서 재귀 함수의 정의부터 다시 세웠다.  
인덱스 i에서 현재 숫자를 건너뛸지, 연속 부분 수열에 포함해 이어갈지(또는 시작/종료할지)를 재귀+메모이제이션으로 탐색해 얻을 수 있는 최대 합을 구하는 방식으로 해야 했다.

인덱스 i의 숫자를 고르거나 고르지 않는 것은 맞지만, 그것이 연속 부분 수열의 시작이되거나 중간이 되거나 종료되는 경우를 따지지 않았다.
