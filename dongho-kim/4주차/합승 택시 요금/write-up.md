# 접근 방법
맨 처음 접근 방법으로는 "다익스트라로 s를 기준으로 모든 노드까지의 최단 거리를 구하고, s에서 a까지 이동하는 경로와 b까지 이동하는 경로를 구한다." 였습니다.  
하지만 반례가 존재했습니다.

두 번째 접근 방법으로는 합승이 효율적인 경우, 합승을 하면 전체 비용이 감소한다는 점을 발견했습니다. 그래서 **S에서 A까지 가는 모든 경로와 S에서 B까지 가는 모든 경로를 구하고 각 두 경로로 이동한다고 할 때의 총 비용을 구합니다.**  
하지만 시간 초과가 발생했습니다.  
시간을 개선하기 위해 두 경로의 총 이동 거리를 구할 때, 한번 구해놓은 경로는 저장해두어 재연산 하지 않도록 구현했습니다.  
하지만 시간 초과, 실패, 컴파일 오류가 발생했습니다.

1시간 15분이 지나 결국 AI의 도움을 받았습니다.

우선, 기존 코드의 문제점으로 다음과 같습니다.
1. `_from`에서 `_to` 까지이 모든 경로를 구하는 연산의 시간 복잡도가 지수적이다. -> 특정 알고리즘을 통해 **'최단 거리'**만 바로 계산해야 한다.
2. 경로(`route`)를 문자열로 처리하고 있다. 만약 노드 번호가 10 이상이면 전체 숫자가 아닌 마지막 한 자리 숫자만 가져온다.

이 문제의 올바른 접근 방법은 **경유지 선정** 입니다.  
풀어서 설명하면 **어느 한 지점(k)까지는 합승하고, 그 지점부터 각자의 집(a, b)까지는 따로 이동한다**.  
이때의 총 비용은 `(s에서 k까지의 최단거리) + (k에서 a까지의 최단거리) + (k에서 b까지의 최단거리)` 입니다.  
따라서 k를 모든 지점으로 가정하고 계산한 다음, 최소값을 찾으면 됩니다.

모든 노드 간의 최단 거리를 구하는 **플로이드 워셜** 알고리즘을 사용하면 매우 간단하게 풀립니다.  
하지만 세 번의 다익스트라 알고리즘으로도 풀리는데, 노드의 개수가 훨씬 많아진다면(예: 1,000개 이상) 다익스트라(Dijkstra) 알고리즘을 세 번 사용하는 방식이 더 효율적일 수 있습니다.  
왜냐하면 플로이드 워셜은 N^3 의 시간 복잡도를 가지지만, 다익스트라 알고리즘은 ElogV 만큼의 시간 복잡도를 가지기 때문입니다.

# 배운 점
1. 완전 탐색 접근법을 조금 더 떠올렸으면 어땠을까 하는 아쉬움이 있다.
2. 그동안 다익스트라를 여러 번 쓸 생각을 못했던 것 같고 목적지로부터 다익스트라를 할 생각도 못했다.
3. [second_solution](./second_solution.py)의 20번 라인에서 `dist[curr] <= w`로 구현했다가 틀렸다. 이미 `dist` 배열에 기록된 더 짧은 경로가 있다면 큐에서 꺼낸 정보는 불필요한 정보가 되기 때문에 이를 처리해주기 위함인데, `dist[curr] <= w` 로 하게 되면 모든 경로에 대해서 건너띄기 때문이다.  
4. 다익스트라에서 최소 힙에 튜플을 넣을 때, 거리가 앞에 오도록 해야 한다. 애초에 다익스트라 알고리즘 자체가 짧은 거리가 갱신이 됐다면 해당 노드부터 새롭게 최단 경로를 탐색하는 알고리즘이기 때문에 이 구조를 지키기 위함이다.
