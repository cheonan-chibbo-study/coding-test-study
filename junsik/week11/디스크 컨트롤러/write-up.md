# 문제

작업의 요청 시간과 작업 시간이 주어질 때, 평균 반환 시간(작업 종료 시간 - 요청 시간)이 최소가 되도록 작업을 처리하는 문제이다.

# 문제링크

https://school.programmers.co.kr/learn/courses/30/lessons/42627

# 문제 접근법

먼저 작업들을 요청 시간 기준으로 정렬하였다.

현재 시간까지 요청된 작업들을 모두 최소 힙(Priority Queue)에 저장하고, 힙에는 `(작업시간, 요청시간)` 형태로 저장하여 작업 시간이 가장 짧은 작업을 우선적으로 선택할 수 있도록 구현하였다.

힙이 비어 있지 않다면 작업 시간이 가장 짧은 작업을 꺼내 현재 시간을 갱신하고, `(현재 시간 - 요청 시간)`을 총 소요 시간에 더하였다.

만약 현재 시간까지 실행 가능한 작업이 없다면 현재 시간을 1 증가시켜 다음 작업이 도착할 때까지 기다렸다.

모든 작업을 처리한 후 총 소요 시간을 작업의 개수로 나누어 평균 반환 시간을 구하였다.

# 전에 풀었던 것과 달라진 점

* 이전에는 Priority Queue의 동작 원리를 이해하는 데 집중했다면, 이번에는 의사코드만 보고 전체 알고리즘을 직접 구현하였다.
* `time`, `idx`, `sum` 변수가 각각 어떤 역할을 하는지 명확하게 이해하고 구현하였다.
* 작업을 힙에 하나씩 넣는 것이 아니라 **현재 시간까지 도착한 작업을 모두 힙에 넣은 후**, 그중 작업 시간이 가장 짧은 작업을 선택해야 한다는 흐름을 직접 구현하였다.
* `priority_queue<pair<int, int>>`에 `(작업시간, 요청시간)` 순서로 저장하는 이유를 이해하고 코드에 적용하였다.

# 느낀점

처음 풀었을 때는 Priority Queue를 언제 사용해야 하는지 감이 잘 오지 않았지만, 다시 풀어보면서 "현재 실행 가능한 작업 중 우선순위가 가장 높은 작업을 반복해서 선택한다"는 패턴을 확실히 이해하게 되었다. 또한 의사코드부터 작성한 뒤 구현하는 방식으로 접근하니 전체 흐름을 놓치지 않고 코드를 작성할 수 있었고, 앞으로 비슷한 스케줄링이나 Priority Queue 문제도 같은 방식으로 접근할 수 있을 것 같다는 자신감이 생겼다.
