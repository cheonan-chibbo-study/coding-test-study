# 문제

숫자로 이루어진 문자열에서 정확히 `k`개의 숫자를 제거하여 만들 수 있는 가장 큰 수를 구하는 문제이다.

# 문제링크

https://school.programmers.co.kr/learn/courses/30/lessons/42883

# 문제 접근법

스택(Stack)을 이용하여 현재까지 선택한 숫자를 관리하였다.

숫자를 앞에서부터 하나씩 확인하면서, 현재 숫자가 스택의 맨 위 숫자보다 크고 아직 제거할 수 있는 횟수(`k`)가 남아 있다면 스택의 맨 위 숫자를 제거하였다. 이 과정을 더 이상 제거할 수 없을 때까지 반복한 뒤 현재 숫자를 스택에 넣었다.

모든 숫자를 확인한 후에도 `k`가 남아 있다면, 뒤쪽 숫자를 제거하는 것이 가장 유리하므로 스택의 맨 위에서 남은 개수만큼 제거하였다.

마지막으로 스택에 남아 있는 숫자를 문자열로 옮기고, 스택은 LIFO 구조이므로 `reverse()`를 이용하여 순서를 뒤집어 정답을 반환하였다.

# 전에 풀었던 것과 달라진 점

* 이전에는 스택을 사용하는 이유와 `while`문의 동작을 이해하는 데 집중했다면, 이번에는 의사코드만 보고 전체 알고리즘을 직접 구현하였다.
* 현재 숫자가 이전 숫자보다 크다면 이전 숫자를 제거해야 가장 큰 수를 만들 수 있다는 그리디(Greedy) 아이디어를 코드로 구현하였다.
* 모든 숫자를 확인한 뒤에도 `k`가 남아 있을 수 있다는 점을 고려하여, 스택의 뒤쪽 숫자를 제거하는 후처리를 직접 구현하였다.
* 스택은 LIFO 구조이므로 결과 문자열이 거꾸로 만들어진다는 점을 이해하고 `reverse()`를 이용하여 올바른 순서로 변환하였다.

# 느낀점

처음에는 어떤 숫자를 제거해야 가장 큰 수가 되는지 직관적으로 판단하기 어려웠지만, 다시 풀어보면서 현재 숫자보다 작은 이전 숫자를 제거하는 것이 항상 최선이라는 그리디 전략을 이해할 수 있었다. 또한 스택을 이용하면 이전 숫자를 효율적으로 관리할 수 있다는 점과, 각 숫자는 최대 한 번만 push와 pop되므로 시간 복잡도가 O(N)이라는 점도 함께 이해할 수 있었다. 앞으로 비슷한 그리디 문제에서도 현재 선택이 이후 결과에 어떤 영향을 미치는지를 먼저 생각해 보는 습관을 가져야겠다고 느꼈다.
