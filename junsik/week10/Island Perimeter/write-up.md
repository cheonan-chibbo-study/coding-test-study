# LeetCode 463. Island Perimeter

## 1. 문제

`m x n` 크기의 2차원 배열 `grid`가 주어진다.

* `1` : 육지(Land)
* `0` : 바다(Water)

배열에는 하나의 섬만 존재하며, 상하좌우로 연결되어 있다.

섬의 **둘레(Perimeter)** 를 구하여 반환하는 문제이다.

---

## 2. 문제 링크

https://leetcode.com/problems/island-perimeter/

---

## 3. 문제 접근법

처음에는 이전에 풀었던 섬 관련 문제들처럼 DFS를 사용할 수 있을 것이라고 생각했지만, 이 문제는 모든 육지를 한 번씩만 확인하면서 주변 네 방향만 검사하면 해결할 수 있는 구현 문제였다.

풀이 과정은 다음과 같다.

1. 배열 전체를 순회한다.
2. 현재 칸이 육지(`1`)라면 기본적으로 둘레를 `4` 증가시킨다.
3. 현재 칸의 상, 하, 좌, 우를 확인한다.
4. 인접한 칸도 육지라면 서로 맞닿아 있는 변이므로 둘레를 `1` 감소시킨다.
5. 모든 칸을 확인한 후 최종 둘레를 반환한다.

육지 한 칸은 기본적으로 네 개의 변을 가지고 있지만, 인접한 육지가 존재하면 그 변은 외부와 맞닿아 있지 않으므로 둘레에서 제외해야 한다는 점을 이용하였다.

---

## 4. 소스코드

```cpp
class Solution {
public:
    int islandPerimeter(vector<vector<int>>& grid) {
        int perimeter = 0;

        for (int i = 0; i < grid.size(); i++) {
            for (int j = 0; j < grid[0].size(); j++) {

                if (grid[i][j] == 1) {

                    perimeter += 4;

                    // 위
                    if (i - 1 >= 0 && grid[i - 1][j] == 1)
                        perimeter--;

                    // 아래
                    if (i + 1 < grid.size() && grid[i + 1][j] == 1)
                        perimeter--;

                    // 왼쪽
                    if (j - 1 >= 0 && grid[i][j - 1] == 1)
                        perimeter--;

                    // 오른쪽
                    if (j + 1 < grid[0].size() && grid[i][j + 1] == 1)
                        perimeter--;
                }
            }
        }

        return perimeter;
    }
};
```

---

## 5. 새로 알게 된 점

* 모든 Grid 문제가 DFS나 BFS를 사용하는 것은 아니라는 것을 알게 되었다.
* 육지 한 칸을 발견할 때마다 기본 둘레를 `4` 더하고, 인접한 육지마다 `1`씩 빼는 방식으로 둘레를 계산할 수 있었다.
* 상하좌우를 검사할 때는 항상 배열 범위를 먼저 확인해야 한다.
* 행(`i`)은 위·아래 이동에서, 열(`j`)은 왼쪽·오른쪽 이동에서만 변경된다는 점을 다시 확인할 수 있었다.

---

## 6. 느낀점

이전까지는 섬과 관련된 문제를 풀면서 자연스럽게 DFS를 먼저 떠올렸지만, 이번 문제는 단순히 배열을 순회하며 주변만 확인하면 해결된다는 점이 인상적이었다. 문제의 요구사항에 맞는 알고리즘을 선택하는 것이 중요하다는 것을 다시 느꼈고, Grid 문제에서도 반드시 탐색 알고리즘이 필요한 것은 아니라는 점을 배울 수 있었다. 또한 상하좌우 좌표를 다루는 과정이 반복되면서 Grid 문제의 기본 구현에 더욱 익숙해질 수 있었다.
